# Contributing Guidelines

[简体中文](CONTRIBUTING.md) | **English**

Thank you for contributing to **cfdialog**! This project follows a lightweight but strict source code management standard: **Conventional Commits + SemVer 2.0.0 + CHANGELOG**.

> Related Docs: [README_EN](README_EN.md) | [CHANGELOG](CHANGELOG.md) | [AI Disclosure](docs/AI_DISCLOSURE.md) | [Dev Constraints](docs/DEVELOPMENT_CONSTRAINTS.md).

---

## ⚠️ About AI-Generated Code

Following the [AI Development Guidelines](https://github.com/styisme/ai-development-guidelines), the vast majority of code in this project is **AI-assisted** (especially the single-file architecture, i18n system, and the `demo.py` test suite).

When submitting a PR, you must:
- State whether the changes were generated by AI.
- **Manually verify the functionality** (must run `python -m unittest discover -s tests -v` locally, not just rely on CI).
- If you also used AI, please specify the model and prompt direction in the PR description.

## Local Development

### Requirements

| Component | Version |
|---|---|
| Python | ≥ 3.8 |
| Dependencies | None (stdlib only) |
| Tests | `unittest` (stdlib) |
| CI | GitHub Actions |

### Run / Test

```bash
git clone https://github.com/styisme/cfdialog.git
cd cfdialog

python -m unittest discover -s tests -v
python tools/demo.py --list-langs
python tools/demo.py --auto --ui en < /dev/null
python cfdialog.py          # run the file manager directly
```

### Tool Scripts

| Script | Purpose |
|---|---|
| `tools/demo.py` | Usability tests / interactive menu / `--auto` / `--list-langs` |
| `tools/gen_docs.py` | Generate README / DEVELOPMENT / 开发文档 (writes to repo root when `--out` is omitted; overwrites existing docs) |
| `tools/gen_lang_packs.py` | Batch-generate `lg/*.txt` |
| `tools/make_custom_lang.py` | Interactive single-language-pack maker |

## Commit Convention

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```
<type>(<scope>): <subject>
```

### Allowed Types

`feat` / `fix` / `docs` / `style` / `refactor` / `perf` / `build` / `ci` / `chore`

### Common Scopes

`browser` / `manager` / `i18n` / `cli` / `elevation` / `partitions` / `tests` / `docs`

## Pull Request Process

1. Fork the repo
2. `git checkout -b feat/your-feature`
3. Modify + run tests locally
4. Commit with Conventional Commits
5. Push and open a PR
6. Wait for CI + review

### PR Description Should Include

```markdown
## Changes
Briefly describe what was done

## Change Type
- [ ] feat / fix / refactor / docs / chore

## Related Issue
Closes #123

## Testing
- [ ] python -m unittest discover -s tests -v passed
- [ ] python tools/demo.py --list-langs passed
- [ ] python -m compileall -q cfdialog.py tools examples passed

## AI Generated?
- [ ] Yes (specify model and manual verification)
- [ ] No
```

## Versioning Rules

Follow [Semantic Versioning 2.0.0](https://semver.org/):

| Change | Version Bump |
|---|---|
| Incompatible changes | **MAJOR** |
| Backwards-compatible features | **MINOR** |
| Bug fixes | **PATCH** |

⚠️ **IMPORTANT**: There is **no automatic version injection**. Before a release you must manually:

1. Update `LIB_VERSION` in `cfdialog.py` (if present)
2. Update the version badge in `README.md` / `README_EN.md`
3. Add `## [x.y.z] - YYYY-MM-DD` to `CHANGELOG.md`

## Troubleshooting

**Q: Tests fail with `FileNotFoundError: cfdialog.py`?**
A: Run `python -m unittest discover -s tests -v` from the repo root; `tests/test_smoke.py` locates the root via `parents[1]`.

**Q: `tools/demo.py --list-langs` shows fewer languages?**
A: Check `lg/` contains zh_TW/ja/ko/ru/fr/es/ar. `ar` is a placeholder pack (Arabic for `prompt_*`, English for the rest).

**Q: `gen_docs.py` writes into `tools/`?**
A: Without `--out` it defaults to the repo root (already patched). Run `python tools/gen_docs.py` from the repo root.

**Q: CI `demo --auto` is red?**
A: That job is informational (`continue-on-error: true`). Click into the Summary / Artifacts for full output. To fix the `ar` case, see `docs/DEVELOPMENT_CONSTRAINTS.md`.

**Q: Why is `cp` allowed in read-only mode?**
A: `cp` only stores picks in the in-memory clipboard; `ps` actually writes to disk, so it is disabled.
